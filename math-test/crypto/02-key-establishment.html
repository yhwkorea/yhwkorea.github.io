현대 암호학 · 키 설정

DH와 KEM은 메시지를 암호화하는 것이 아니다

공개 채널에서 짧은 공유 비밀을 만든 뒤 KDF와 AEAD에 넘기는 과정을 봅니다.

1. Diffie–Hellman의 결과

DH/ECDH에서 Alice와 Bob은 각자 비밀값을 고르고 공개값만 교환해 같은 군 원소를 계산합니다. 그 결과는 보통 그대로 AES 키로 쓰지 않고 KDF의 입력으로 사용합니다.

Alice: secret a, public A     Bob: secret b, public B
       DH(a,B) = shared = DH(b,A)
       shared ──KDF(context)──▶ traffic keys

2. DH만으로는 중간자 공격을 못 막는다

공격자가 Alice에게는 자기 공개값을, Bob에게도 다른 자기 공개값을 주면 두 개의 안전한 채널 사이에서 메시지를 중계할 수 있습니다. DH는 공유 비밀을 만들지만 상대의 이름을 인증하지 않습니다. 인증서와 전자서명 또는 사전에 공유한 인증 정보가 필요합니다.

3. ephemeral 키와 forward secrecy

세션마다 새 DH 비밀값을 만들고 폐기하면 장기 인증키가 훗날 노출되어도 기록된 과거 트래픽을 곧바로 복호화하기 어렵게 할 수 있습니다. 장기 서명키와 세션 키 합의키는 역할이 다릅니다.

4. KEM 인터페이스

KEM은 세 알고리즘을 가집니다.

KeyGen() → (pk, sk)
Encaps(pk) → (kem_ciphertext, shared_secret)
Decaps(sk, kem_ciphertext) → shared_secret 또는 암묵적 실패값

KEM ciphertext에는 큰 사용자 메시지가 들어 있지 않습니다. shared secret에서 KDF로 키를 만들고 AEAD로 실제 본문을 보호합니다.

5. ML-KEM

ML-KEM은 FIPS 203으로 완성된 모듈 격자 기반 KEM입니다. ML-KEM-512·768·1024는 서로 다른 보안 파라미터 세트이며 AES 키 길이 숫자와 직접 비교하는 표기가 아닙니다.

핵심 계산은 다항식 벡터와 작은 오차를 포함한 선형 관계입니다. 비밀 없이 공개 관계에서 짧은 구조를 복원하기 어렵다는 Module-LWE 계열 가정을 사용합니다.

decapsulation 실패

실패 이유를 분기·시간·오류 메시지로 노출하면 chosen-ciphertext 공격의 단서가 될 수 있습니다. 표준 구현의 검증·재암호화·암묵적 거부 절차를 임의로 생략하면 안 됩니다.

6. HQC

HQC는 quasi-cyclic 오류정정부호 문제에 기반합니다. NIST가 2025년 ML-KEM과 다른 기반의 추가 KEM 표준화 대상으로 선택했지만, 현재 완성된 FIPS는 아닙니다.

공개 데이터에는 오류가 섞인 선형 부호 관계가 들어가고, 비밀 구조를 아는 수신자는 오류를 정정해 공유 비밀을 복원합니다. ‘선정됨’은 설계가 더 이상 바뀌지 않거나 모든 프로토콜 배포가 승인됐다는 뜻이 아닙니다.

7. 고전+PQC 하이브리드

전환기에는 X25519 같은 고전 키 합의와 ML-KEM을 함께 사용해 어느 한 계열만 깨져도 즉시 전체 비밀이 사라지지 않도록 결합할 수 있습니다. 단순히 두 바이트열을 붙이는 것이 아니라 downgrade 방지, transcript binding, KDF 문맥을 포함한 프로토콜 정의가 필요합니다.
